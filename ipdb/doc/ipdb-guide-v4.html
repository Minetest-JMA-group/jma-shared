IPDB · moderator guide

Records are buckets. These animations show exactly how the buckets change.

Follow the motion, not the jargon: a login links two records, a merge fuses them, the merge log preserves the originals, and manual tools let you move identifiers around.

01 · Link + merge

Watch the login connect the records, pull them together, and fuse them into one.

The important part is the motion: the login creates the link, the two records physically converge, and their data flies into one unified record.

Connect → converge → fuse → reconcile
Two records exist: Frosty is on A, while the login's IP is on B.
Watch what moves. Nothing in the animation jumps straight to the end state.
02 · Why a plain undo fails

After fusion, the live record no longer contains the old seam.

You still know all the identifiers and punishment values. What disappeared is the information about which original bucket each one came from.

Unified record → old seam disappears → split becomes guesswork
The merged record still knows what it contains — but not which original record owned each piece.
03 · Merge log + rollback

The safety net is created before the merge happens.

The original records are duplicated into the merge log. The log also points at the new merged record, so rollback can restore the saved originals exactly.

Copy → stamp → point → merge → restore
Before merging, IPDB makes full copies of both originals. That is what makes rollback safe.
04 · Isolate

Isolate physically cuts one identifier out and gives it a brand-new record.

/ipdb isolate Kestrel99

Lift the identifier → cut it free → grow a clean record → drop it in
The old record keeps everything else. The new record starts clean and contains only the identifier you isolated.
05 · Move

Move is a single-identifier relocation — no merge of the surrounding data.

/ipdb move 88.14.201.9 Frosty

Select one IP → route it to the destination record → settle it there
Only that one identifier changes address. Nothing else is merged and the surrounding record data stays where it was.
Keep this mental model
Link → mergeTwo live records become one unified record.
Merge log → rollbackCopies made before the merge let IPDB restore the originals without guessing.
Isolate / MoveManual tools reorganize identifiers without pretending two records were never separate.
Mute and ban are separate. When both originals have a mute, the longer mute wins. When both have a ban, the longer ban wins. A merged record can still contain both a mute and a ban at once.

Watch the objects, not the terminology.

When you can see the identifier chips, the records, the merge boundary, and the snapshot copies physically move, the rules become much easier to reason about.
